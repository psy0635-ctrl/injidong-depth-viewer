# RGB 인덱스 호환 개인 검토본 — 2026-10-16

개인 검토 브랜치에서 구현·검증한 모바일 인수 검사기 정책이다. 팀 공식 승인·공용 통합은 미완료이며, 공통 FramePacket v1.0.0 스키마와 baseline을 변경하지 않았다. 과거 기록은 [2026-10-14 검증 요약](mobile-session-intake-validation-20261014.md)에 그대로 보존한다.

## 문제와 변경

기존 `check_mobile_session.py`는 `files.phone_rgb_index="rgb_index.jsonl"`을 포함한 files 사전 전체를 고정 비교하고, 이후 읽기·미참조 분류에도 같은 파일명을 직접 사용했다. 새 실제 세션 `d405_1792065733288`은 `files.images_index="images.jsonl"`을 사용해 기존 검사기가 `unexpected mobile file layout`으로 종료 1, 연결 CLI가 종료 20으로 중단했다. 기존 Windows 실행 복사본과 그 실패 보고서는 수정하지 않았다.

`mobile-rgb-index-compat-review-v1`은 위 두 키/파일명 조합 중 정확히 하나만 허용한다. 교차 조합, 두 키, 두 루트 인덱스 엔트리, 선언되지 않은 다른 인덱스 엔트리를 거부한다. 두 엔트리의 내용이 같아도 거부하며, 선택 파일 손상·누락 시 fallback이나 입력 변경을 하지 않는다. 디렉터리·깨진 링크도 후보 엔트리로 관찰하고 symlink·Windows junction/reparse point를 lstat으로 거부한다. 선택 파일은 일반 파일이어야 한다.

선택을 한곳에서 수행하고 결과를 files 검증·인덱스 읽기·해시 보고·참조 분류에 사용한다. 기존 RGB 행·FramePacket·NPZ·raw·IMU·개수 검증은 유지한다. `rgb_index` 보고 객체에 정책 ID, 후보 키/엔트리, 선택 키, 선언 경로, 사용 경로, 실제 해시와 실패 이유를 보존한다. 읽지 못한 해시는 null이다. 기존 보고 필드와 종료 코드 의미는 유지한다.

runner의 실제 `validate_report()`는 두 형식의 성공·실패 보고서를 추가 필드와 함께 수용했다. runner 소스는 수정하지 않았다. 기존 `mobile_commit_reference`는 과거 검사 기준 앱 커밋이지 이번 APK의 소스 커밋 증거가 아니다.

## 2026-10-16 로컬 커밋 전 최종 검토

위 절의 commit 미실행은 구현·검증 단계의 이력이다. 후속 요청은 같은 개인 검토 브랜치에서의 로컬 커밋까지이며 push·PR·merge·fetch는 포함하지 않는다. 시작 시 현재 여섯 변경 파일의 전체 diff가 기존 외부 `full_review.diff`와 같고, 검사기 바이트 해시가 실제 촬영본 실행 기록과 같음을 다시 확인했다. 이전 테스트·촬영본 실행 로그는 덮어쓰지 않는다.

최종 검토에서 기존 목록은 CRLF 작업 파일 바이트를 기록하지만 `core.autocrlf=true`인 Git은 LF blob을 저장하여 네 항목이 불일치하게 됨을 확인했다. 루트 `.gitattributes`에 목록 대상 다섯 파일과 목록 자체만 `text eol=lf`로 지정하고 해당 파일만 LF로 맞춘 뒤, 실제 작업 파일과 staged blob 해시를 각각 목록과 대조한다. baseline_hashes.json은 줄바꿈 표기만 맞추며 내용과 기존 Git blob은 같고, 별도 baseline의 코드·스키마와 보호 경로는 변경하지 않는다.

검사기와 두 테스트 모듈은 줄바꿈을 제외한 내용이 이전 검토본과 같다. 두 정상 형식의 보고·runner 수용 사례만 추가 확인하고, 이미 통과한 전체 테스트는 반복하지 않는다. 파일 검사 동작 변경이 없으므로 실제 촬영본 실행 결과는 동일한 코드 내용에 결합된 이전 근거를 유지한다. 최종 검토·stage·커밋 SHA와 잔여 상태는 새 외부 커밋 검토 보고서에 기록한다. 팀 승인·공용 통합 미완료와 다섯 false 상태는 그대로다.
